# ADR-0029: Walking skeleton (milestone M1)

- **Status:** Accepted
- **Date:** 2026-10-30
- **Deciders:** Product owner

## Context

M1 connects all layers end to end: log in, see the office, walk, see others. Several building blocks
were still open.

## Decision

| Topic              | Decision                                                                                                                                                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Demo office        | Floor plans are **JSON seed files** in the canonical floor-plan format (the same format the editor will write in M5). They are imported into **PostgreSQL** (via MikroORM) on startup if missing.                                |
| Demo floors        | **Ground floor** like the design mockup (open space, meeting rooms Elbe and Alster, kitchen, lounge); **upper floor** with lounge, terrace and a stage for later town halls. Multiple floors are part of the MVP.                |
| Avatar             | A real **glTF** model, generated by a **Blender Python script** in the repository (`tools/blender/`), with skeleton and idle/walk animations.                                                                                    |
| Movement input     | **Click-to-walk** (server-side A\*) **and keyboard** (WASD/arrow keys) with client-side prediction.                                                                                                                              |
| Web login          | **oidc-client-ts** (authorization code + PKCE) against Keycloak.                                                                                                                                                                 |
| Token verification | **jose** with Keycloak's JWKS, behind a `TokenVerifier` port (issuer, audience `teamtown-api`, expiry).                                                                                                                          |
| WebSocket server   | The **ws** library in the server's own `realtime` module, attached to the Fastify HTTP server; routing via the contract-first envelope. Authentication with a first `Authenticate` command (browsers can't send auth headers).   |
| Desktop login      | Included in M1 (ADR-0023). The **Electron main process** runs the flow (system browser, `teamtown://` deep link, PKCE) and keeps the refresh token encrypted with `safeStorage`; the UI only receives short-lived access tokens. |
| Asset licence      | 3D models, graphics and the brand artwork are licensed **CC BY-SA 4.0** (`LICENSE-ASSETS`). Code, including the Blender scripts, stays AGPL-3.0.                                                                                 |
| Trademark          | The name "TeamTown" and the logo are **not** licensed for use as the name or logo of forks (`TRADEMARKS.md`).                                                                                                                    |

## Consequences

- The floor-plan format becomes a contract (`packages/contracts`) and gets a JSON Schema-like Zod definition.
- Git LFS is required for `.glb`/`.blend` files; CI checks out LFS objects.
- Desktop login can't be fully automated in CI (system browser); its parts are unit-tested and the flow is tested manually.
